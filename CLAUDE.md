## Stack & conventions

- **No bundler.** Every page is a standalone `.html` file that links `css/style.css` and `js/main.js` directly. Edit files in place; there's nothing to compile.
- **Fonts:** Inter via Google Fonts CDN.
- **Smooth scroll:** [Lenis](https://github.com/darkroomengineering/lenis) v1.3.26 via CDN (`unpkg.com`) — animates real `window` scroll (not a transform wrapper), so `position: sticky` and scroll-spy keep working. Initialized in `js/main.js`. Skips init if `prefers-reduced-motion` is set.
- **JS architecture:** everything lives in one IIFE in `js/main.js`, guarded per-feature (`if (someElement) { ... }`) so the same file works unmodified across all pages regardless of which components a given page has.
- **BEM-ish class naming**, e.g. `.case-study__card`, `.case-detail__box`, `.work-filter__tab`.

## Design tokens (all in `css/style.css` `:root`)

- **Colors:** `--color-white #fff`, `--color-dark #212121`, `--color-bg-soft #f5f5f5`, `--color-muted #8a8a8a`, `--color-border #d9d9d9`, `--color-accent #e2ef72` (status dot pulse, quote marks, callout accent bars, lock/list badges).
- **Typography scale — semantic, not literal to Figma.** Figma's literal sizes were intentionally overhauled into semantic roles:
  - `--fs-caption` 13px (chips, footer, tooltips), `--fs-label` 14px (buttons, nav), `--fs-body` 16px (paragraphs, quotes), `--fs-title` 18px (card titles), `--fs-heading` 24px (section H2s, hero greeting/tagline), `--fs-display` 36px (hero name/curtain-label base — curtain label uses `calc(var(--fs-display) * 2)`), `--fs-hero` 64px (homepage headline "Designer. Builder. Marathoner. In that order.", added when the hero was rebuilt), `--fs-quote` 64px (404 page's giant "404" — no longer used by testimonials, see below).
  - Each scales down further at `≤1023px` and `≤599px` breakpoints (see `:root` media queries) — `--fs-hero` specifically: 64px → 48px → 40px.
  - Line-heights: `--lh-tight` 1.2, `--lh-snug` 1.3, `--lh-normal` 1.5, `--lh-relaxed` 1.6.
- **Radius:** `--radius-sm` 8px, `--radius-md` 12px, `--radius-lg` 20px, `--radius-full` 50px.
- **Container:** max-width 1280px, padding 80px desktop → 40px tablet → 20px mobile (`--container-pad` / `--container-max`).

## The `.case-detail__*` component system (shared by all 3 case study pages)

Introduced with `case-study-gokomodo.html` and reused verbatim (per explicit user instruction: "same format, design language and interaction, down to responsive") for the other two. Core pieces, all in `css/style.css`:

- `.case-detail__section` → `.case-detail__label` (sticky icon + `<h2 class="section-heading">`) beside `.case-detail__card` (bg-soft outer wrapper) → one or more `.case-detail__box` (white inner card).
- Inside a box: paragraphs, `.case-detail__callout` (accent-bar highlight, bold lead-in via `<strong>`), `.case-detail__image`, `.case-detail__stats`/`.case-detail__stat` (2-col grid of number+label), `.case-detail__impact-card` (bordered box, label+copy — can also just wrap a single bold-embedded sentence with no separate label, and can itself nest a `.case-detail__stats` grid, as in the WhatsApp funnel case study's "Funnel Metrics").
- **Spacing is margin-based, not `gap`**, specifically so a heading can sit *closer* to the paragraph directly under it than to whatever comes before/after: `.case-detail__box > * + * { margin-top: 24px }`, overridden to `16px` only for `.case-detail__box > h3 + p`. **Known trap, hit twice:** any descendant selector added later for a specific element inside a box (e.g. `.case-detail__callout`, `.case-detail__stat-value`) that sets its own `margin` at equal specificity to the sibling-margin rules will silently win by source order and collapse the spacing back to 0/default. Fix is always to either delete the element's own redundant `margin: 0` (let the box-level reset handle it) or bump the element's selector specificity (`p.case-detail__stat-value` instead of `.case-detail__stat-value`) — don't just add a plain single-class override, check which one already applies.
- Case study 3 (Klinik Tani) introduced two more reusable pieces used nowhere else yet: `.case-detail__tags` (grid of accent-colored pill labels, e.g. "pest infestations") and `.case-detail__list`/`.case-detail__list-item`/`.case-detail__list-number` (numbered list with a circular accent badge).
- Every case study page's curtain uses a non-default theme (`--curtain-bg: #E2EF72; --curtain-color: #212121`, label text "Case Study") instead of the site default — set via inline `style` on `.page-curtain` in each page's HTML *and* mirrored in `js/main.js`'s `CURTAIN_THEMES` map (keyed by filename) so the sweep leaving one case study or entering it from elsewhere both use the same theme. `PAGE_LABELS` and `CURTAIN_THEMES` in `js/main.js` both need a new entry any time a new case-study page is added — easy to forget one of the two.

## Notable architecture/UX decisions (with reasoning, so they aren't accidentally reverted)

- **Case-study carousel (`index.html`)**: real "push" slide transition (translateX track, not fade), with a hidden clone of the *first* slide appended so the infinite loop always slides forward (never snaps backward). Autoplay uses `setTimeout` + elapsed-time tracking (not `setInterval`) so pausing on hover/focus and resuming continues from the correct remaining time instead of restarting. Dot progress-bar fill is a CSS animation synced to the same timing. Nav dots (`[data-carousel-dot]`) are hand-authored in the HTML, one per *real* slide — if the real slide count ever changes, the dot count must be updated by hand too (JS reads `caseStudyDots.length` dynamically, it doesn't generate them).
  - **Bug fixed once:** flex children need a *definite* width for percentage `flex-basis` to resolve correctly — track/slide widths are set via inline styles computed in JS from the actual slide count, not hardcoded CSS percentages.
- **`work.html` reuses `index.html`'s case-study card styles** — `.case-study__body` is shared between the carousel's `.case-study__slide` and the static work-list cards, so visual changes to one should usually apply to both (this now also applies to `.case-study__soon`/tooltip on the Coming Soon card).
- **Nav scroll-spy** only tracks `<a href="#...">` links, filtered out of the page-link list *before* building the section-index map.
- **Sliding nav indicator** (`.site-nav__indicator`): the pill background that highlights the current/hovered nav link now glides between links (JS-measured `offsetLeft`/`offsetWidth`/`offsetHeight`, animated via `transform`) instead of each link instantly toggling its own background. No-JS fallback (`:not(.has-nav-indicator)`) still exists so an instant background swap works if JS fails. **Bug fixed once:** the indicator's height/vertical position was originally driven by CSS `top:0; bottom:0`, which stretched it to the *pill's* full padded height instead of the individual link's height, making it look oversized — fixed by having JS also set `height`/`translateY` explicitly, matching the width/left approach.
- **Testimonials carousel**: scroll-snap track, arrow buttons scroll by one card width. Custom mouse-drag-to-scroll (mousedown/mousemove/mouseup + a `didDrag` guard to stop the drag from also firing a click) was built, then **deliberately removed** at user request after a trial — arrow buttons + native trackpad/touch scroll were judged sufficient, and the drag code added real complexity for a narrow benefit (desktop users with a plain mouse, no trackpad). If asked to add drag-to-scroll back, this exact implementation is recoverable from git history / this note, but don't re-add it preemptively.
  - **Bug fixed once:** the track-wrap used to bleed past the container via negative margin + `padding-inline` (so the last card could scroll flush to the edge). `scroll-snap-type` doesn't treat plain `padding` as a valid rest position, so the *first* card's snap point ended up flush with the bled edge instead of aligned with the container padding like every other section. Fixed by adding `scroll-padding-inline` alongside the visual `padding-inline`. This entire bleed approach was later removed anyway (per user request, the track now sits flush inside the container like everything else) — but the underlying `scroll-padding` lesson applies to any future bled/padded scroll-snap container.
  - Quote-mark glyph (`.testimonial__quote-mark`) is now an `<img>` (`assets/icons/ic-quote-mark.svg`, provided by the user directly, not fetched from Figma) — was previously a styled Unicode `&#8220;` character.
- **Page-curtain transition**: diagonal clip-path wipe between page navigations, reverse-engineered from `https://motion.dev/ui/components/page-curtain`.
  - `js/main.js` intercepts clicks on same-origin `<a>` links, plays a "cover" animation (`CURTAIN_SWEEP_DURATION`, 500ms, matches the CSS `page-curtain-cover` animation), waits `CURTAIN_HOLD_DURATION` (currently 80ms) before the real navigation. **This value has been tuned back and forth** — originally 450ms, cut to 80ms for feeling laggy, at one point the *sweep itself* was also shortened to 350ms then explicitly reverted back to 500ms because only the post-sweep hold was meant to be trimmed, not the sweep's pace. If asked to adjust curtain timing again, be precise about which of the two (sweep vs. hold) the user means.
  - **Per-destination theming**: `CURTAIN_THEMES` in `js/main.js` lets specific destinations override the default dark-bg/white-text curtain via CSS custom properties (`--curtain-bg`/`--curtain-color`) set inline on `.page-curtain`. Currently only case-study pages use this (accent lime bg, dark text). Any link whose destination isn't in the map explicitly `removeProperty`s the override so it correctly falls back to default — this matters for e.g. leaving a case-study page back to Work/About.
  - Curtain label font-size is `calc(var(--fs-display) * 2)`.
  - Each page's curtain defaults to the fully-covered CSS state (no JS needed); an inline `<script>` right after `<body>` triggers the reveal. Curtain label text is hardcoded per page in the HTML (JS-injected text doesn't reliably render before unload). Panel and label are separate elements, not parent/child.
- **Lenis `scrollTo()` anchor offset**: don't pass `offset` — target's CSS `scroll-margin-top` (110px) is already respected automatically.
- **`about.html`**: Professional Experience accordion via `grid-template-rows: 0fr → 1fr` — the collapsing element must carry *no padding* (padding lives on the inner `<p>` via margin instead). Toolkit logos reuse `.clients__track`.
- **A custom inverted cursor** (mix-blend-mode circle following the pointer, fine-pointer-only) was built at one point and **removed in full** shortly after per user feedback ("too much") — if this ever comes up again, treat it as a considered-and-rejected idea, not an oversight.
- **A "wave reveal" hover effect** on the case-study CTA buttons (inspired by a 21st.dev component) was also built and **fully reverted** ("jelek banget") — same as above, don't reintroduce without being asked.

## A testing quirk worth knowing (not a site bug)

The local `file://` browser preview tool used for QA in this project has been **unreliable across multiple sessions**, in escalating ways:

1. Mildest form: serves **stale cached CSS/JS** after edits, even after a fresh navigation. Workaround: re-inject a cache-busted `<link>`/`<script>` tag (`?v=" + Date.now()`) via `javascript_exec` before checking anything, and prefer waiting for the element's `onload` (or polling `document.styleSheets`) over a fixed `setTimeout`, since a bare short wait can still race the load.
2. Worse form (seen repeatedly in the session that rebuilt the hero and added case studies 2–3): `css/style.css` **fails to load entirely** for an entire session — `document.styleSheets` shows only the external Google Fonts/Lenis links, no local stylesheet, no matter how many fresh tabs/navigations/cache-busts are tried. This is *not* fixable from the assistant side; it's an environment issue, not a code issue. When this happens: verify changes via the file on disk directly (`Read`/`grep`) and via DOM structure/text-content checks in the (unstyled but structurally-correct) preview rather than visual screenshots, and be upfront with the user that visual verification isn't possible that session — ask them to check in their real browser instead. Don't burn many turns re-attempting the same preview reload once this pattern is confirmed (2-3 tries across fresh tabs is enough to confirm it's systemic, not a one-off).
3. Real-mouse-driven state (`:hover`, drag) is **not reliably simulated** by this tool's `computer` actions or `dispatchEvent`-based synthetic events either — confirmed via `el.matches(':hover')` returning `false` right after a "hover" action. For anything gated on genuine `:hover`/drag, verify the *logic* via direct DOM state checks (classList, computed styles after manually toggling the relevant class/property) rather than trying to trigger the real pseudo-class.
4. Also: `javascript_exec`-triggered `window.location.href` navigation doesn't actually navigate in this tool — only real simulated clicks do.

None of the above are things to "fix" in the site; they're preview-tool limitations to route around.
